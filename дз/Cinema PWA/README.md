
## Запуск в Visual Studio Code

Откройте папку **Cinema PWA**, затем терминал PowerShell. Node.js — 24 или новее. На этом компьютере библиотеки уже установлены; при переносе без node_modules выполните `npm.cmd ci`.

Для демонстрации PWA:

```powershell
npm.cmd run demo
```

Команда собирает приложение и запускает собственные PocketBase и Vite preview. Сайт: **http://127.0.0.1:4176/**. База: **http://127.0.0.1:8093/_/**. Остановка — Ctrl+C в терминале запуска. Если адрес уже доступен, повторный запуск не требуется.

Для редактирования с быстрым обновлением:

```powershell
npm.cmd run dev
```

Сайт разработки: http://127.0.0.1:5176/. Service worker в dev выключен; офлайн проверяется после сборки в режиме demo.

## Проверки

```powershell
npm.cmd run build
npm.cmd run lint
npm.cmd test
npm.cmd run test:feedback
```

`npm.cmd test` запускает 33 автоматические проверки расчётов, офлайн-хранилища, очереди сообщений и push. Они используют подставные сетевые ответы и временные данные; настоящие push-уведомления не отправляются.

`test:feedback` самостоятельно запускает временную копию PocketBase на свободном локальном порту. Рабочая база читается только для создания согласованного снимка; тестовые сообщения записываются в отдельную временную базу.

## Демонстрация офлайн

Откройте афишу онлайн, дождитесь подготовки service worker, затем откройте «Мои билеты». Остановите собственный запуск через Ctrl+C и обновите страницу: сохранённые данные и изображения остаются доступны. Прямой вход в зал или оформление без API блокируется. Простое отключение Wi-Fi не отключает локальный сервер.

История привязана к ключу этого браузера и адреса. Другой браузер, порт или устройство имеют отдельную историю. Исходные покупки сохранены в базе и доступны администратору. В IndexedDB контакты покупателей не записываются. После отмены история перепроверяется сервером.

## HTTPS и телефоны

Приложение и база остаются на компьютере; CloudPub даёт публичную HTTPS-ссылку к сайту на 4176. Прямое соединение телефона с компьютером по Wi-Fi и установка локальных сертификатов для этого способа не нужны.

В первом терминале, в папке Cinema PWA:

```powershell
npm.cmd run demo
```

Во втором терминале, в папке с clo.exe, для повторного запуска уже сохранённой публикации:

```powershell
.\clo.exe run
```

Первоначальная настройка CloudPub выполняется один раз:

```powershell
.\clo.exe login
.\clo.exe publish -H "Host:localhost:4176" http 127.0.0.1:4176
```

Оба терминала должны работать для онлайн-функций. На телефоне откройте выданную CloudPub HTTPS-ссылку: на iPhone — в Safari → «Поделиться» → «На экран Домой», на Android — в Chrome → меню → «Установить приложение». После установки запустите приложение со значка онлайн, дождитесь загрузки афиши и затем проверяйте офлайн-режим.

Не удаляйте сохранённую публикацию: смена адреса создаёт для браузера другое хранилище и отдельную историю покупок. Подключение к CloudPub не переносит историю с 127.0.0.1 и не объединяет разные устройства в аккаунт. Факт установки, push и системное меню значка на каждом физическом телефоне нужно проверять отдельно.

Документация CloudPub: https://cloudpub.ru/docs/ и https://cloudpub.ru/docs/faq.


## Обратная связь

Ссылка находится внизу афиши; прямой адрес: http://127.0.0.1:4176/feedback. Форма доступна после первого онлайн-посещения и без сервера. Сообщение сначала сохраняется в IndexedDB и отображается как «Ожидает отправки». Подтверждение API меняет статус на «Отправлено». Ниже формы остаются все ожидающие/отклонённые сообщения и десять последних подтверждённых сообщений этого браузера. Полученные сообщения администратор видит в коллекции `feedback` PocketBase.

При наличии Background Sync очередь обрабатывает service worker. Если API не поддерживается или запрещён, сообщения повторно отправляются при открытом приложении после успешной проверки связи. Работа с закрытой вкладкой зависит от браузера и его настроек. Сценарий обновления остаётся стандартным: после первого посещения новой сборки закройте вкладки и окна Cinema PWA этого браузера и откройте приложение снова. Данные сайта удалять не нужно.


## Быстрые действия значка

В манифест добавлены три shortcuts к существующим страницам. В поддерживающих браузерах/ОС они доступны через меню установленного приложения: в Windows — правой кнопкой по значку на панели задач или в «Пуске», на поддерживаемых мобильных устройствах — долгим нажатием по значку. Обычный файловый ярлык на рабочем столе может иметь другое меню.

Для демонстрации сначала соберите проект через `npm.cmd run demo`. Если запуск уже работает, остановите его через Ctrl+C в своём терминале и запустите заново. Содержимое манифеста можно проверить в инструментах разработчика: Application → Manifest → Shortcuts. Наличие действий в системном меню зависит от браузера и обновления метаданных установленного приложения; подробный порядок проверки записан в файле третьего этапа.

## Push-уведомления

Страница: http://127.0.0.1:4176/notifications. Ссылки «Уведомления» находятся внизу афиши и страницы билетов. Запуск — прежней командой `npm.cmd run demo`. Она автоматически поднимает обработчик push в том же управляющем Node-процессе на внутреннем loopback-порту 8094. Vite передаёт `/api/push` этому обработчику, остальные `/api` — PocketBase.

На этом компьютере контакт отправителя уже настроен с разрешения пользователя. Закрытый VAPID-ключ и подписки хранятся в служебном файле `pocketbase/pb_data/web-push/state.json`. Папка pb_data исключена из Git и закрыта от раздачи сервером разработки; в dist её содержимое не попадает. При переносе без служебных данных ключи создадутся заново; для первой настройки нужно задать настоящий контакт отправителя через серверную переменную `PUSH_VAPID_SUBJECT` и повторно включить подписку в браузере. Формат указан в .env.example; префикс VITE_ для этих настроек не используется.

Нажмите «Включить уведомления» и самостоятельно подтвердите разрешение браузера. Затем нажмите «Отправить тест через 10 секунд» и закройте вкладку. Терминал demo и браузер как программа должны продолжать работать. Тест открывает «Мои билеты» по нажатию. Кнопка «Отключить уведомления» отменяет подписку браузера, удаляет её на сервере и отменяет ещё не отправленный тест.

Это серверный Web Push через службу браузера, а не уведомление по таймеру React. Для отправки/получения нужен интернет; локальный адрес 127.0.0.1 подходит для компьютерной проверки, телефоны требуют своего доступного HTTPS-адреса. Таймер теста и его статусы живут до перезапуска сервера; ключи и подписки сохраняются. Подтверждены реальная доставка при закрытой вкладке и переход по нажатию во встроенном браузере. Физические телефоны, отдельные Яндекс/Edge и полное завершение браузера пока не проверены.

Новая серверная зависимость — `web-push` 3.6.7. После переноса проекта библиотеки устанавливаются через `npm.cmd ci`. Для тестов `npm.cmd test` используется отдельная временная папка и имитация ответа службы push, без настоящей рассылки. Напоминания о реальных сеансах пока не добавлены: реализован первый согласованный тестовый сценарий.
